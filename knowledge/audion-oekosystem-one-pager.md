# AUDION × CHECKION × PLEXON – One-Pager (Enablement)

**Ausführliche Fassung:** [`audion-oekosystem-enablement-und-plugin-strategie.md`](./audion-oekosystem-enablement-und-plugin-strategie.md) · **Funktionen & Use Cases:** [`audion-funktionen-und-use-cases.md`](./audion-funktionen-und-use-cases.md)

---

## In einem Satz

**AUDION** macht aus Research **befragbare Personas und Journeys** – **CHECKION** speist **Web-Realität** (Scans, Topics) ein, **PLEXON** liefert **Login, Profil, Token-Transparenz** und **Boards**, auf denen KI **AUDION- und CHECKION-Tools gemeinsam** nutzt.

## Kernbotschaft

*„Die Zielgruppe ist kein statisches PDF – sie wird zum Gesprächspartner in jedem Tool, das ihr freischaltet: Browser, Figma, PowerPoint, IDE/Board – mit einem konsistenten Modell und nachvollziehbarer Nutzung.“*

---

## Drei Säulen

| | **Rolle** | **Nutzen** |
|--|-----------|------------|
| **AUDION** | Personas, Zielgruppen, Chat, Journeys, Ingestion, AI Assist, Plugins | Validierung aus **Nutzerperspektive**, Journey-Arbeit mit Research-Anker |
| **CHECKION** | Scans, Klassifikation, Site-Topics, MCP | **Schnellerer Start** für Personas/Zielgruppen; **Alignment** mit öffentlicher Site |
| **PLEXON** | Auth, Profil, Usage → Tokens, Board + MCP | **Ein Account**, Budget-Klarheit, **eine KI-Session** für AUDION + CHECKION |

## Synergien (kurz)

| Paar | Mehrwert |
|------|----------|
| **AUDION + CHECKION** | Site-Topics & verknüpftes CHECKION-Projekt → reichere **Vorschläge** (Topics = Scanner-Metadaten, keine User-Zitate). |
| **AUDION + PLEXON** | Zentraler Login/Profil; **report_usage** → Tokens; Board: **AUDION MCP** + **CHECKION MCP** gemerged. |

---

## AUDION überall: Integrationsmatrix

| **Einstieg** | **Nutzen für den Kunden** |
|--------------|---------------------------|
| Web-App | Volle Administration, Upload, Settings |
| REST API | Eigene Systeme, Mobile (später) |
| AUDION MCP | Agenten: Personas, Journeys, AI Assist |
| PLEXON Board | Workshops: eine Prompt-Karte, **beide** Welten |
| Figma Plugin | Auswahl + Screenshot → **Persona-Feedback** im Design |
| PowerPoint Add-in | Story/Slides → **Persona-Dialog** |
| Tavus (optional) | Video-Gespräch mit Persona-Replica |

**Prinzip:** API-first, ein Datenmodell; MCP und Plugins bringen **dieselbe** Logik in den **Arbeitskontext**.

---

## Nutzen in vier Stufen

1. **Operativ:** Validierung **am Artefakt** – weniger Tab-Wechsel.  
2. **Methodisch:** Lebende Modelle statt Archiv-PDFs.  
3. **Ökonomisch:** Mehr Iteration, weniger Panel; **Token-Sicht** über PLEXON.  
4. **Strategisch:** Ein Bild aus **Web (CHECKION)**, **internem Wissen (AUDION)** und **Team-Flow (Plugins/Board)**.

## Vier Szenarien

| Szenario | Kurz |
|----------|------|
| Segment-Launch | AUDION: Personas + Messaging-Chat · CHECKION: Topics aus Scan · PLEXON: Login + Usage |
| Design Review | Figma-Plugin + optional Scan-Abgleich · Board: KI fasst zusammen |
| Executive Brief | PowerPoint + Persona · Domain-Themen aus CHECKION · Profil zentral |
| Agentic Flow | MCP listet Personas/Journeys · CHECKION-Kontext · Cursor/Board als Orchestrator |
